1:1 매칭 자체만 보면:

- 처리군 1,410개가 모두 매칭됨
- 각 처리군에 서로 다른 통제군 1개
- 따라서 1,410 + 1,410 = 2,820개

그런데 `caliper(0.05)`와 `common`을 추가하면 1,410개 모두의 매칭을 보장하지 않습니다.

- `common`: 점수의 공통 범위 밖에 있는 처리기업을 제외
- `caliper(0.05)`: 가장 가까운 미사용 통제기업도 점수 차이가 0.05를 넘으면 해당 처리기업을 매칭하지 않음
- `noreplacement`: 앞에서 사용한 통제기업을 뒤에서 다시 사용할 수 없음

| 사양 | 매칭된 처리군 | 매칭된 통제군 | 총기업 |
|---|---:|---:|---:|
| caliper 없음 | 1,410 | 1,410 | 2,820 |
| `caliper(0.05) common` | 1,379 | 1,379 | 2,758 |

1. 최종 실행에서는 `caliper(0.05)`가 없었다.
2. `caliper`가 있어도 모든 1,410개가 통과하는 다른 propensity-score 모형 또는 데이터 버전을 사용했다.
3. `_weight==1`만 센 것이 아니라, 매칭되지 않은 treated까지 별도로 포함했다.
4. 다른 실행의 `_weight`가 데이터에 남아 있었다.

| Treated / Control minimum·maximum | 각 집단의 성향점수 범위 |
| Common-support lower·upper bound | 두 집단 성향점수 범위가 겹치는 구간 |
| Propensity-score estimation N | 성향점수가 있는 기업 수 |
| Within / Outside support N | 겹치는 구간 안·밖의 기업 수 |
| Final matched N | 최종 매칭 기업 수 |

**다만 지금 코드는 세 군데 수정해야 합니다.**

1. `treated_max`, `control_max`에 `r(min)`이 들어가 있습니다. **`r(max)`가 맞습니다.**
2. `support_lower`, `support_upper`를 계산하는 줄이 없습니다.
3. 공통지지 진단인데 **매칭된 기업만으로 범위를 계산**하고 있습니다. 매칭 전 추정 표본에서 계산해야 제외된 기업도 확인할 수 있습니다.

scalar treated_max = r(max)

quietly summarize _pscore if VD_Backing == 0 & psm_esample, meanonly
scalar control_min = r(min)
scalar control_max = r(max)

scalar support_upper = min(treated_max, control_max)
